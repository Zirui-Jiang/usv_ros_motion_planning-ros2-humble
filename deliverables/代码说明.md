# 代码说明

这是一套基于 **ROS 2 Humble + Gazebo Classic** 的无人艇导航仿真代码，以 Otter 双推进器船模为对象。主要过程是：获取船舶状态和障碍地图，规划航行路径，生成参考轨迹，再由控制器计算左右推进器指令。

当前默认算法组合为 **A* 路径搜索 → LOS 轨迹生成 → PID 控制**，也支持 Dijkstra、GBFS 和 LQR。导航算法与业务节点主要使用 Python，仿真插件和部分感知支撑使用 C++。以下路径均相对于压缩包内的 `usv_code/`。

## 1. 目录怎么看

```text
src/
├── core/                         核心业务代码
│   ├── perception_module/        感知：LiDAR 建图、障碍代价地图
│   ├── decision_module/          决策：目标管理、路径搜索、轨迹生成
│   ├── control_module/           航控：轨迹跟踪、PID/LQR、推进器输出
│   ├── shared/                   公共模型、配置解析、模块间消息
│   └── mission_module/           值守、圆形巡航、阵位保持等任务代码
├── sim_env/                      仿真启动、船模、场景、定位与显示资源
├── plugins/                      Gazebo/RViz 插件及配置生成工具
└── user_config/                  场景选择与障碍物生成配置
scripts/                         构建、启动和测试等辅助脚本
```

`*_module` 只是按职责分类的目录；带 `package.xml` 的目录才是 ROS 功能包。功能包内的 `launch/` 放启动脚本，`config/` 放参数，`test/` 放测试。

同名目录嵌套是 Python 功能包的常见组织方式。例如 `control_module/controller/` 是 ROS 包，里面的 `controller/` 才是 Python 算法模块。

## 2. 一次导航如何运行

1. **仿真提供输入**：Gazebo 模拟船舶运动和 LiDAR；当前船位、艏向、速度及 TF 坐标变换来自仿真真值。
2. **感知维护地图**：LiDAR 建图与 Nav2 实时代价地图分别工作，决策和航控读取障碍代价地图。
3. **决策生成参考**：收到目标点后，搜索全局路径，再通过 LOS 生成带时间、位置和速度信息的参考轨迹，并检查轨迹碰撞风险。
4. **航控计算输出**：结合实际船舶状态和参考轨迹，调用 PID 或 LQR，发布左右推进器命令，并检查当前船体占用情况。
5. **状态反馈闭环**：航控向决策回传执行状态；决策负责目标替换、取消和任务完成等处理。

决策到航控使用 `navigation/reference` 话题传递完整轨迹，航控通过 `navigation/control_report` 返回状态。`global_path` 和 `local_trajectory` 话题用于可视化。

## 3. 建议从这些文件开始看

| 想了解什么 | 对应文件 |
| --- | --- |
| 整套仿真如何启动 | `src/sim_env/launch/main.launch.py`，具体组合逻辑在 `src/sim_env/sim_env/launch_support.py` |
| 感知如何组织 | `src/core/perception_module/usv_perception/usv_perception/launch_support.py`；建图算法在 `src/core/perception_module/perception/perception/mapping.py` |
| 目标、规划与任务状态如何调度 | `src/core/decision_module/usv_decision/usv_decision/decision.py`；规划执行逻辑在同目录 `runtime.py` |
| 路径搜索怎样实现 | `src/core/decision_module/path_planner/path_planner/graph_planner/astar_planner.py` |
| 路径怎样变成参考轨迹 | `src/core/decision_module/trajectory_planner/trajectory_planner/los_trajectory_planner.py` |
| 航控如何接收轨迹并输出推进器命令 | `src/core/control_module/usv_control/usv_control/control.py` |
| PID、LQR 的具体算法 | `src/core/control_module/controller/controller/pid_controller.py` 和同目录 `lqr_controller.py` |

阅读时先看启动组合，再看 `decision.py` 和 `control.py` 的输入输出，最后进入具体算法文件。这样容易区分 ROS 通信、任务调度和数值计算各自负责什么。

## 4. 数据结构与参数在哪里

- **船舶状态与控制输出**：`src/core/shared/common/common/models.py` 定义 `VesselState`、`ControlCommand` 等公共数据结构。
- **轨迹数据结构**：`src/core/decision_module/trajectory_planner/trajectory_planner/trajectory.py`；轨迹包含时间、累计距离、位置、艏向、曲率、速度和加速度。
- **模块间消息**：`src/core/shared/usv_navigation_interfaces/msg/`，其中 `NavigationReference.msg` 是轨迹参考，`ControlReport.msg` 是航控反馈。
- **算法和船型参数**：集中在 `src/core/shared/usv_navigation/config/`，包括路径规划、LOS、PID/LQR 和 Otter 船型参数。
- **建图与代价地图参数**：在 `src/core/perception_module/usv_perception/config/`。

控制算法的主要调用形式是 `compute(state, trajectory, dt) -> ControlCommand`。其中 `state` 是实际状态，`trajectory` 是期望轨迹，`dt` 是控制周期时间间隔。输出的 `left/right` 是 `[-1, 1]` 范围的归一化推进器命令，不直接表示推力牛顿值。

`mission_module` 的任务代码保留在工程中，普通导航主入口不启动这些任务。当前代码尚未实现 AIS/导航雷达融合、COLREGs 决策、DWA 或 MPC。
