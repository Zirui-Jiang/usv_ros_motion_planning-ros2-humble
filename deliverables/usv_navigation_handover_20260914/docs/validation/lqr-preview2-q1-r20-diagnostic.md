# LQR 两秒预瞄、低位置权重候选的数值诊断

本记录只支持选择下一轮 Gazebo 参数候选，不代表 ROS 集成或 Gazebo 闭环验收通过。未修改生产配置、LQR A/B、Riccati 方法、LOS 数值实现或 signed u/v/r 语义。

## 独立配置与来源

候选文件为 `scripts/validation/config/lqr_preview2_q1_r20.yaml`。它复制当前完整 controller 层级，保留 `control_frequncy` 拼写和全部 PID 数值；仅将所选控制器设为 lqr，并设置 LQR：

```yaml
Q_matrix_diag: [1, 1, 100, 10, 10, 10]
R_matrix_diag: [20, 20]
lookahead_time: 2.0
max_iterations: 5000
solve_timeout: 0.08
```

Q 的次序是 `[x, y, psi, u, v, r]`，R 的次序是左右推进器。Qx 与 Qy 相等，避免改变航线方向时交换沿程与横向权重。原控制频率 10 Hz、离散步长 0.1 s、solve_eps=0.1、目标位置容差 1 m、速度完成容差 0.25 m/s 均保留。

数值调用使用 WSL Ubuntu-22.04 工作区 `/home/usv/usv_migration/python`，提交 `1a82de47a21238b7c5b8e1c3794db5eb5ae7235a`，Python 3.10.12、NumPy 1.21.5。实际导入的 lqr_controller.py SHA256 为 `d78049e5d6477255e7a327dd21f5b688909b669236e54f969875c7609aefccc7`。这些候选参数在诊断脚本中通过字典传入，没有修改 WSL 或 Windows 生产 YAML。

## 为什么撤回零预瞄候选

此前纵向标量回放固定 v=r=0，能够显示永久位置领先造成的满推，却不能检验横荡—艏摇稳定性。真实 Gazebo 随后出现持续转圈，因此不能把该标量结果推广为零预瞄的完整闭环有效性。

直接调用现有 `discrete_model` 和 `solve_gain`，在 psi_ref=0、u_ref=1 时，完整 A+BK 最大特征根模约 0.939675；把 x/y/psi 误差归零后的 (u,v,r) 主子块出现特征根 1.104551。其 (v,r) 主子块为：

```text
[[ 0.942594719, -0.071297359],
 [-2.071416391,  0.192556496]]
```

该子块特征根约为 1.104535 和 0.030616。这解释了每次以实际位姿重建轨迹、查询初始参考时，所保留速度反馈不一定稳定。该子块分析是理想化误差重置模型，不声称完全等同于 ROS 异步时序。

另外，以真实 LOS 重建和随参考重算的 K 构造两拍局部数值映射，旧 Q/R 配合 0.1 s 和 0.5 s 预瞄仍有模大于 1 的特征根。候选恢复 2 s 引导，降低位置权重并增加输入惩罚。目标前方 12 m、实际 u=1 时，旧 2 s 配置原始左右命令约 7.96776/8.35187；本候选约 0.20132/0.22686，尚未触及 [-1,1] 限幅。

## 有横向扰动的原离散模型回放

轨迹与控制调用真实 Python 类；运动推进使用原 `discrete_model(theta=0, velocity=1)` 得到的冻结 A/B，按 `z_next=A@z+B@command` 推进。这是直航工作点附近的线性诊断，不是完整非线性船舶、Gazebo、波浪或障碍环境。状态顺序为 `[x,y,psi,u,v,r]`，初始状态 `[0,0.05,0.03,0,0.01,0.01]`，固定路径从 `[0,0,0]` 到 `[12,0,0]`。

控制周期为 0.1 s，LOS 每 0.2 s 以当前状态重算；LOS 输出间隔 0.5 s、时域 20 s、空间前视 1 m、减速分母下限 3 m。每拍采用真实推进器限幅和完成/SETTLING 判断；TIMEOUT 当拍零推力，随后继续。若 |psi|>0.5 rad 或 |y|>2 m 则中止，避免继续解释超出小角模型适用范围的结果。

在相同确定性输入下运行三次，目的是采集计算耗时波动，不构成三个独立随机场景：

| 指标 | 结果 |
| --- | ---: |
| 三次完成状态 | 均达到位置与速度完成条件 |
| 完成时间 | 14.2 s |
| 首次进入 1 m 容差圈 | 13.8 s |
| 入圈速度 | 0.313676 m/s |
| 峰值速度 | 0.994856 m/s |
| 最大横偏 | 0.092687 m |

上述 P99 仅包含同步数值 compute 调用，不包含 ROS 回调、规划复核、消息处理或 Gazebo，不替代正式 control P99 验收。

## 低速求解预算边界

保持同一 Q/R、5000 次上限和 80 ms 预算，在 WSL 对每个恒定参考速度调用 solve_gain 三次：

| 参考速度 m/s | 收敛迭代数 | 耗时范围 ms | 结果 |
| ---: | ---: | ---: | --- |
| 0.30 | 973 | 14.39–16.23 | 三次收敛 |
| 0.20 | 1447 | 21.73–24.10 | 三次收敛 |
| 0.10 | 2869 | 44.06–49.41 | 三次收敛 |
| 0.06 | 4765 | 69.93–74.61 | 三次收敛，预算余量较小 |
| 0.05 | 未完成 | 80.045–80.059 | 三次均触发时间预算 |

提高迭代上限解决了本回放最大 1070 次的需求，但不保证任意低速参考都能在 80 ms 内收敛。正式 Gazebo 应记录参考最低速度、迭代峰值、TIMEOUT、持续零推力时段、控制 P99、到达时间和全艇几何间隙。若低速前视插值成为真实瓶颈，再评估 LQR 专属的速度参考与位姿预瞄分开；不要直接改变共享参考逻辑影响 PID。
