## 修复跟踪误差的时间权重

旧脚本每 0.1 s 墙钟记录最新姿态。当仿真停止推进时，同一源状态被反复计入。
`e381832` 直航首例有 231 个误差样本却只有 201 个 odom 源时刻；C++ 对应为
245 与 228，暂停发生在不同误差的位置。这会使墙钟停顿改变物理航迹指标的权重。
已知源时间诊断的该例比例仍为 1.12728，并未通过 1.10，所以此次测量修复本身
不能作为该实现已满足对照门槛的证据。旧完整矩阵三次直航源时间比例为
1.127282、1.181543、1.162247，七个有效配对中四个通过；原墙钟六个通过的归档不变。

新的完整复验将显式选择 `source_time_trapezoid`，按同一规则计算所有控制器、场景、
版本和重复序号。参考路径按墙钟接收顺序固定为该目标的首条有效全局路径；
不使用旧 C++ 路径错误的系统时间 header 排序，不在重规划后改变主参考。

观测包含发布目标时最近的 odom，以及随后至 `acquisition_finished` 的全部 odom。
对源时间 `t_i` 和该状态到固定路径的距离 `e_i`，采用

```text
RMSE_t = sqrt(sum((t[i+1]-t[i]) * (e[i]^2+e[i+1]^2)/2)
              / (t[last]-t[first]))
```

积分只覆盖实际观测源状态跨度，不外推至窗口边缘。相同源时间且相同姿态的重复
记录只保留一次并计数；相同源时间却不同姿态、时间回退、非有限值、缺必要字段、
缺参考或无正时间跨度均为 unknown。内部源时间间隔以及首尾覆盖差的上限预先固定为
0.5 s，依据本次工程已有的自船状态有效期，不从各次数据中自动调整。

这是有限状态观测的离散梯形积分，不是连续真实轨迹误差的精确积分。报告同时保存
源状态最大误差/P95、实际最大间隔、首尾覆盖差、源样本数、合并重复数及参考事件行号。
几何安全及到达判据独立执行，不能用源时间 RMSE 较低覆盖这些失败。

坐标系必须相同或具有显式证据。本次仅允许选择本工程已核查的
`otter_fake_localization` 契约：原 C++ 和当前真值定位源码均将 map→odom 定义为
identity，默认 frame 与运行日志一致。比较记录需保存对应源码 SHA 和来源；
不能将这一契约默认应用于任意外部 odom/map 数据。

下一版本真值定位仅新增三个并行数组的长度检查，坐标转换保持不变。
该文件 SHA256 为 `ec5f0d59cc35e6f76066add8cd0e3531d422ae3d7b6f5edfc6566bf800a36068`；
map→odom 的零平移及单位旋转见 `src/sim_env/src/fake_localization_node.cpp` 第 97–102 行。
正式 manifest 必须对应这一源码，运行日志与独立定位 green 还需确认实际 frame 链。

## 对照、性能及证据保留

源时间 RMSE 与到达时间的 Python/C++ 比例仍分别要求 ≤1.10。对照固定使用
`baseline-grid-interior-001` 的相同场景与重复序号；仅双方功能通过的有效记录配对。
该基线最多支持七个 PID 配对；另两条圆柱裕度失败、九条 LQR 无有效基线，保持不可比。

选择的度量，并并列保留原墙钟 RMSE。新规则的回溯诊断必须标注为回溯重算，
不得把它冒充旧试验前已固定的原主判或抹去旧失败。

控制 P99 <100 ms、扫描 P95 不超过输入周期、队列五槽与 0.2 s TF 截止均保持。
完整记录实时运行中的 TF 过期及积压 unknown。独立“正常 TF 已可查”受控建图试验
只补充该条件下的吞吐证据，不将 live unknown 回改为通过。OS 采样需在首 goal 前
