正式 `3afb25f` 转弯 01 源 RMSE 为 0.1045001608 m，对 CPP 同编号的比值为 **1.1091297178，失败保留**。同一提交、同一参数的先前候选为 0.0733022476 m，比值 0.7780055124。这次差异明确集中于前段和中段，不能归因于尾部停止圆或路径终点改变。

诊断只读三份已完成记录，复用 [既有分段脚本](../../source-time-candidate-diagnostics/reproduce.py) 的全量源时间梯形方法。按沿程 `-y-10.125` 的每个源时间区间中点归入 `<3 m`、`3–9 m`、`≥9 m`，没有删除启动、暂停前后或尾部观测；分段只帮助解释，未替代正式指标。结果和来源 SHA 见 [diagnostic.json](diagnostic.json)，复算入口是 [reproduce.py](reproduce.py)。

## 暂停、参考与命令证据

两次 Python 都在中途记录到连续 19 个墙钟 sample 的三轴零命令，以及两个 `SIMULATION_PAUSED` 状态，但暂停发生在不同的转向相位：

|---|---|---:|---:|---:|---|
| 正式 | 6.1→6.2 | 2.083999 | 1.137077 | -1.387102 | (0.838323,-0.085929,0.730651) |
| 候选 | 5.2→5.3 | 2.173470 | 0.548857 | -1.979788 | (0.616734,0.296212,0.349606) |

正式恢复后的首观测航向为 -1.326033 rad、横向位置 23.373262 m，候选为 -1.932914 rad、23.302241 m。两者暂停前的横向位置和偏航角已不同；没有证据将全部差异归因于暂停。CPP 也有 1.703488 s 和 0.502326 s 的 odom 接收空隙，且其日志没有 Python 的状态遥测；不能假设 CPP 无暂停。

Python 除启动、中途暂停和终点 settling 外，未在本记录的墙钟 sample 中发现额外的连续全零命令组。正式启动是 3 个零命令 sample、候选为 2 个；两者末端均有 26 个。sample 是最近接收值的快照，并非每次控制计算的原子记录，所以该观察不能证明所有控制周期绝无遗漏。

用最新已接收轨迹重构的预瞄方向显示，正式约 3 m 处实际航向 `-1.41513 rad`，参考约 `-1.62456 rad`，确有向路径回转的需求；约 6 m 处则实际 `-1.61994`、参考 `-1.56758 rad`，处在相反的回摆阶段。参考接收、状态更新和控制回调并不同步，这些值说明闭环存在相位差，不能充当逐命令的精确输入证据。

## 对 2.7 s 候选的判断边界

将 2.6 s 改为 2.7 s，在 LOS 航向变化达到 0.3 rad/s 上限的局部区间，预瞄航向最多改变约 0.03 rad；这是明确可测试的微小参数变化。在最初左右推进器已饱和为 `1/-1` 时，额外航向需求不会增加该饱和命令；中段回摆的两个方向也不会都因更早预瞄而必然改善。

现有数据支持“需要改善前中段转向及横偏残差”，不能证明“2.7 s 必然改善正式转弯 01”。同版本两次结果相差也伴随控制启动和暂停相位差，因此后续若测试 2.7 s，应在采集前固定完整重复编号、继续保存启动/暂停/零命令证据，并保持相同源时间度量和 1.10 门槛。不能把候选最好的一次替换正式 01。

同轮正式转弯 02、03 源 RMSE 比值分别为 **0.7178558587、1.0219110836**，均通过；没有依据将转弯 01 的失败概括为所有转弯场景一致退化。
