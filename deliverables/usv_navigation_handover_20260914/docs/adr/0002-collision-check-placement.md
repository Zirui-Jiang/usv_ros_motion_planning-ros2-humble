# 普通导航碰撞检查的部署位置

用户在 Q7 允许航控读取地图，并在 Q10 确认：轨迹碰撞检查留在决策规划侧，当前实际船体占用检查保留在航控的控制周期内。这对应此前讨论的候选 B。

地图仍由感知模块维护。航控读取地图以检查当前船体占用，不由此获得地图维护权。这项决定保留现有检查的职责和局部顺序，不新增推进器指令预测检查，也不保证拆分后的通信时序与原单节点完全相同。

## 取舍

| 方案 | 收益 | 代价 |
|---|---|---|
| A：检查留决策，发送限时许可（未选用） | 碰撞逻辑集中，航控接口不依赖地图 | 检查与控制之间增加通信和调度，许可失效处理也需要另行设计 |
| B：轨迹检查留决策，当前船体检查随航控（已确认） | 当前船体检查与本周期控制相邻执行，接近现有顺序 | 航控需要读取地图；地图时效、船体参数及坐标定义需要保持一致 |

此前“检查全部留决策、航控接收限时许可”的推荐已撤下。Q10 只确认检查位置，不确认执行许可、控制会话或具体消息字段。
