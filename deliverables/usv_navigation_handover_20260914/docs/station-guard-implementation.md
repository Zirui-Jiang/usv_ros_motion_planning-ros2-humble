## 固定需求

- Python 任务模块集成现有 A* / LOS / PID-LQR，唯一 ROS 推力出口。
- 待机值守：经纬度、航速、过点精度、值守半径；先回中心，越界回中心，持续障碍监测。
- 绕圆：切向候选规划、连续解析圆引导，顺逆时针、圈数和时长；先到限制即返中心待机。
- 栅格避障，不包含 AIS/Radar 跟踪、CPA 或 COLREGs；保存原任务，安全退出后恢复。
- 阵位：现有双推进器，允许转艏恢复位置，再保持目标固定艏向；无横向推力。
- WGS84 经纬度，外部艏向为真北零度顺时针；地理原点来自活动 world。
- ROS 类型化服务、YAML/CLI、RViz 可视化；兼容原 goal/cancel_navigation。
- 首轮位置/艏向目标 0.5 m / 5°，收敛后的固定60秒窗口联合达标率至少95%。
- 示例 speed=.5 m/s、tolerance=.5 m、watch/orbit radius=10 m；圈数/时长0不限，按仿真时间计时。
- 当前实体船体碰撞、陈旧输入、取消及回退时零输出；零推力不等于瞬停。

## 实施决策

- 保留原导航链的单点到达行为，连续圆规划使用 goal=None，任务到达由状态机消费。
- 类型化 `SetMission` 服务请求完整校验后原子替换任务，拒绝的请求不破坏旧任务。普通 `/otter/goal` 沿用先清除当前任务、再校验目标的旧语义，无效 goal 也可能终止原任务。
- 使用当前工作目录的新分支开发，WSL另建独立构建区，保留基线安装。
- 本轮归档可应用源码补丁与交付报告，不暂存或提交共享根工作区中其他任务的改动；并行雷达代码不进入本次验证版本。
- 候选选定时先迁移参考代次再接收已验证路径，避免清空最优切向路径。
- 同一控制周期的任务tick使用同一时间，避免墙钟重取导致假回退。
- 活动任务同步PID热更新，拒绝使当前圆速度/半径不再可行的yaw_rate_max更新。
