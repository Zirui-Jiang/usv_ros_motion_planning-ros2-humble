# COLREGs + A* + LOS 会遇实验台 · V2

这是一个供人工试用、检查规则逻辑的二维行为原型。它沿用本项目的**全局航路 → LOS 时间轨迹 → 航控跟踪**分工。V2 在 A* 搜索中加入临时通行约束，修补受到会遇影响的航路，再用 LOS 回验和执行；原始全局航路始终保留，用于让清后恢复。

旧版入口保存在 `colregs-demo-v1.html`，可对照其预设侧向路点方案。V2 的单文件入口仍是 `colregs-demo.html`。

## 打开与试用

直接双击本目录的 **`colregs-demo.html`**，用 Edge 或 Chrome 打开。这个文件包含所有 CSS 和 JavaScript，离线可运行，不需要 ROS、Node、Python 或网络连接。

推荐第一次这样试：

1. 选择“对遇”，点击“开始仿真”，以 4× 或 8× 播放。
2. 对比原航路、修补航路和 LOS 轨迹；打开“规则 / 安全区”和“搜索展开点”图层，查看约束区域与搜索节点。
3. 点击“重置并切换规则对照”，观察关闭规则后的原 A* + LOS 行为。
4. 选择“左舷交叉”，比较“目标船配合避让”开与关。
5. 选择“岸障与交叉会遇”，打开“候选航路”，观察静态障碍、规则区域与动态预测如何共同决定候选的接受或拒绝。
6. 暂停后拖动船位、调整目标艏向或参数，尝试构造失败场景；点击“导出本次记录”保留结果。

### 操作语义

- **重置**保留当前参数与拖动后的初始船位，仿真时间归零。
- **切换场景**恢复该场景默认速度、间距、LOS 参数和船位；保留规则与目标配合开关。
- **修改参数／规则开关**重新开始场景，便于同初值比较。
- **目标艏向**按正北 0°、顺时针增加显示；算法内部 yaw 按正东 0、逆时针正。
- **单步**推进 1 秒，“推进 10 秒”适合快速查看阶段。空格可播放／暂停（输入框聚焦时不拦截）。
- 暂停时拖动船图标，将当前画面中的船位作为新的初始状态；滚轮缩放，海图右上角定位按钮恢复视野。
- 右上角下载按钮保存海图 PNG；场景下方的导出按钮保存参数、状态、原航路、当前航路、LOS 轨迹、历史航迹、日志以及 V2 的规则区域、搜索信息、候选代价和回验结果 JSON。

## 算法对应关系与边界

| 部分 | Demo 的实现 | 与运行系统的关系 |
| --- | --- | --- |
| 原始全局航路 | 八邻域 A*、二值障碍、障碍膨胀、可见线简化 | 保留 A* 思路，未完整复刻 Nav2 软代价、未知格和膨胀逃逸语义 |
| 航路修补 | 规则区域及有向边约束参与 A* 搜索，连接到原航路前方重接点 | 新增的待检验工程策略，不是已经接入 ROS 的功能 |
| 规则层 | 会遇责任记忆、约束生成、航速上限、驶过让清与恢复 | 规则区域是规划约束，不作为岸障或真实船体绘制 |
| LOS | 普通路径分支逐式移植，输出时间、弧长、位置、艏向、曲率、速度、加速度 | 来自 `src/core/decision_module/trajectory_planner/trajectory_planner/los_trajectory_planner.py` |
| 轨迹默认参数 | 0.5 s 输出，20 s 参考时域，1 m 预瞄，0.3 rad/s 偏航上限 | 对应当前项目普通 LOS 配置的主要参数 |
| 候选检查 | LOS 外推 + 目标匀速预测 + 静态障碍、规则区域检查 | 有限时域近似；不等同于真实航控执行轨迹 |
| 运动跟踪 | 有界速度、转向响应及终点减速的二维模型，跟踪当前时间参考速度 | 未接真实 PID/LQR/ADRC、推进器或 Gazebo 水动力 |
| 目标输入 | 单目标真值与可选合作行为 | 未接 AIS、雷达跟踪或融合 |

### V2 如何调整航路

1. **保存原航路。** 初始 A* 航路作为不可变参考；会遇中另外保存并执行修补航路。
2. **锁定会遇责任并生成约束。** 用相对位置、速度和 CPA 预测冲突点构造有界安全区域及非对称规则区域。在冲突航段、尚未取得右侧净距的位置限制向左扩展；已取得右侧间距后允许 LOS 正常纠偏，区域检查继续有效。矩形形状、尺寸、触发门限以及追越时的右侧选择均为演示工程策略。
3. **A* 搜索至前方重接点。** 区域和方向同时约束节点、边与航路简化。搜索代价为 `边长 + 偏离权重 × 到原航路距离 × 边长`，偏离权重非负，欧氏距离为启发函数。只移除共线冗余点，避免简化后穿越约束。
4. **LOS 回验与候选排序。** 对搜索净空和航速组合生成 LOS 轨迹，检查岸障、规则区域和预测动态间距。通过回验的候选按完整航路代价与时间惩罚排序；导出的搜索记录另保留到重接点的原始图代价。无可行解则明确显示失败与制动状态。
5. **按事件更新。** 开始避让、让清恢复、目标明显机动或回验失败时重新搜索；稳定期间复用航路并更新 LOS。让清后解除临时规则区域，接回保存的原航路。

这里的最优性范围很有限：A* 求解的是**给定约束、固定重接点及离散图中的代价最小路径**；航速、搜索净空只比较本轮有限候选。这个结论不延伸到连续空间、完整任务或实际跟踪轨迹。二维冻结规则区域也不是时空 A*，动态安全仍依赖有限时域预测回验。

场景采用演示船体与航速，**不代表 Otter 或企业实船参数**。规则适用场景限定为普通机动船、互见条件；未覆盖完整 COLREGs、能见度不良、船舶特殊操纵状态、狭水道和分道通航。

CPA 只根据当前瞬时速度作匀速外推，DCPA 与实际最小间距不是同一指标。画面的期望安全圆环和间距均按**船舶中心距离**解释；碰撞判定采用简化几何近似。风险窗口、角度、让清门限均为工程参数。无可行候选时显示不可行并尝试制动；页面不会将制动标成安全保证。

**到达任务终点与完成追越是两个事件。** 当前追越场景中，候选代价和动态回验可能选择降速跟随。若到达演示终点时尚未驶过并让清，页面仍显示会遇责任未解除，不能把这次到达计为成功追越。

## 文件与维护

| 文件 | 职责 |
| --- | --- |
| `colregs-demo.html` | 给试用者的单文件离线入口 |
| `colregs-demo-v1.html` | 升级前版本，供行为对比 |
| `engine.js` | 不依赖 DOM 的规则状态、A*、LOS 与仿真推进 |
| `app.js` | 海图绘制、交互、数据面板和导出 |
| `page.html`、`style.css` | 页面结构与样式 |
| `build.py` | 将上述源文件合成独立 HTML，无第三方依赖 |
| `engine.test.cjs` | 关键数值行为与默认闭环场景检查 |
| `verify_los.py` | 直接导入原 Python LOS，与 JavaScript 逐点核对 |
| `browser_check.py` | Playwright 浏览器交互检查与截图 |
| `run_scenarios.cjs` | 独立批量推进默认场景，核对到达、碰撞、原航路保留与搜索事件 |
| `validation/`、`audit-v2/` | 数值报告、浏览器报告、截图与独立场景报告 |

修改源文件后，在仓库根目录重新生成 HTML：

```powershell
python scripts/colregs_demo/build.py
```

复现验证（需要 Node、Python NumPy、Python Playwright 及 Chromium）：

```powershell
node scripts/colregs_demo/engine.test.cjs
node scripts/colregs_demo/run_scenarios.cjs
python scripts/colregs_demo/verify_los.py --output scripts/colregs_demo/validation/v2/los_report.json
python scripts/colregs_demo/build.py
python scripts/colregs_demo/browser_check.py
```

验证报告记录被测文件哈希；修改引擎或重新构建后应重新运行相应检查。默认场景通过仅代表这些设定下的行为；拖动位置、改变航向／航速后出现不可行或碰撞，是这个原型需要帮助发现的情况。

### V2 定版核验（2026-09-15）

- 引擎测试通过；独立审计运行 7 场景 × 规则开关共 14 组，7 组规则开启场景均到达演示终点且未触发近似碰撞。追越组保留“会遇责任未解除”结局，不计为完成追越。
- 规则开启场景的全程最小中心间距为 18.1～75.0 m，默认期望间距为 18 m。报告见 `audit-v2/scenario-report.json`。
- 浏览器 15 组检查通过，包含真实规则区域、搜索证据、正速可执行候选、图层绘制、5 秒搜索复用、参数、拖动、导出和手机布局；见 `validation/v2/browser_report.json`。
- JavaScript LOS 与仓库 Python LOS 的 11 组用例、165 个采样点、每点 8 字段一致到数值精度，最大绝对误差 `1.776e-14`；见 `validation/v2/los_report.json`。
- `validation/v2/verification_manifest.json` 记录被测文件哈希、HTML 内嵌源码一致性及截图。以上检查未运行 ROS/Gazebo、真实船舶或其他浏览器内核。

规则依据：[IMO COLREGs](https://www.imo.org/en/about/conventions/pages/colreg.aspx)、[USCG 条文，采用国际规则部分](https://www.navcen.uscg.gov/navigation-rules-amalgamated)。
