# 统一控制指令流的历史提案（未确认）

此提案建立在此前候选 A“检查全部留决策、航控接收限时许可”之上。用户 Q10 已选择当前船体占用检查随航控执行，因此本提案不再作为当前推荐。保留 proposed 状态仅表示它从未被用户确认；实现不得以此为需求依据。

原提案曾讨论以 `ControlDirective` 统一承载轨迹、执行许可和暂停／撤销，并使用会话及序号识别消息。统一消息、许可机制、启动确认及有效期机制均未被用户确认。Q10 不代表用户否定所有消息编号方法，相关接口仍待需求澄清后再讨论。

Q12 随后已明确任务行为：单个模块进程重启后，需要重新下发目标才能执行。这项确认不等于接受本历史提案中的会话绑定或启动确认机制。

首版只验证同机运行（Q9），不附加多机负载测量要求。已确认条件与未决问题以[拆分需求澄清记录](../distributed-navigation/requirements-clarification.md)为准。
