# LOS 预瞄与参考速度的有界诊断

Kd_course=0.10 三次转弯确实减少偏航回摆，但三次源时间 RMSE 均比原 Kd0 记录增大。现有证据支持“更强阻尼没有自动带来更小横偏”；其功能通过不能覆盖冻结源协议的失败。

在四个真实记录状态上调用当前 Python LOS，查询时间从 2.6 s 延长至 3.0 s 均降低参考速度，初始状态还增大转向需求。不过中段航向变化并非始终加强纠偏，因此这里仅提供下一候选的机制依据，不能预测其闭环通过。

本目录没有修改算法、默认配置、原始事件或评分门槛，没有启动 Gazebo。结果见 [diagnostic.json](diagnostic.json)，复算入口为 [reproduce.py](reproduce.py)。

## Kd0 与 Kd.10 的真实三次转弯

固定重复编号逐一对比：Kd0 来自 `python-grid-endpoint-final-matrix-001`，Kd.10 来自 `python-pid-course-d010-turn-candidate-001`。均为原始完成记录，没有用其他重复替换。按源时间对全部误差平方作梯形积分，沿程 `<3 m / 3–9 m / ≥9 m` 用区间中点分段；角速度 RMS 也使用相同源时间区间权重。这里的 Kd.10/Kd0 比值是机制诊断，正式门槛仍使用固定 CPP 基线。

| 重复 | 全程源 RMSE：Kd0→Kd.10 / m | 比值 | 中段局部 RMSE：Kd0→Kd.10 / m | 中段 r RMS：Kd0→Kd.10 / rad·s⁻¹ |
|---|---|---:|---|---|
| 01 | 0.104500→0.117951 | 1.12872 | 0.112094→0.127990 | 0.317274→0.099636 |
| 02 | 0.082896→0.100577 | 1.21329 | 0.085423→0.109817 | 0.313084→0.114705 |
| 03 | 0.080742→0.109788 | 1.35974 | 0.082940→0.123471 | 0.264091→0.115943 |

中段角速度 RMS 降低约 69%、63%、56%，而中段误差增大。Kd.10 减 Kd0 的整段 MSE 分段贡献（前/中/尾，m²）分别为：

- 01：`+0.0011174 / +0.0017983 / +0.00007645`。
- 02：`+0.0011211 / +0.0020545 / +0.00006833`。
- 03：`+0.0017980 / +0.0035961 / +0.00014003`。

三次都是前中段为主要增量。共同路线 `x=23.25 m` 的右侧残差没有随回摆幅度一起消失：中段平均 x 从 `23.35544/23.32758/23.32783` 增至 `23.36859/23.35240/23.36536 m`。Kd.10 中段平均实际速度还略低：原 `0.68807/0.68459/0.68822`，新 `0.66706/0.67846/0.68042 m/s`，所以不能把这批结果简单解释为“中段速度更高导致更大误差”。

冻结 CPP 配对的 Kd.10 源比值为 `1.25189/0.87096/1.38953`，仅 1/3 通过；原 Kd0 为 `1.10913/0.71786/1.02191`。记录不同次试验的这种关联不能取代严格的单一因果辨识，但足以否定“降低回摆即完成修复”的判断。

## 船首未对准时的合推检查

用真实收到的三轴命令，与其接收前最近 odom 配对；轴接收跨度不超过 0.01 s。`L+R>0.1` 只是诊断标记，不是新增验收门槛。初始 `[1,-1]` 的合推为零；右桨反推减弱时，合推变正。

| 重复 | 首次 L+R>0.1 的航向：Kd0→Kd.10 / rad | 同刻合推：Kd0→Kd.10 | 首次越过 −π/2 的 x：Kd0→Kd.10 / m |
|---|---|---|---|
| 01 | -0.0703→-0.0459 | 0.1181→0.1639 | 23.29853→23.29811 |
| 02 | -0.0685→-0.0564 | 0.1145→0.1773 | 23.29577→23.30461 |
| 03 | -0.1230→-0.0548 | 0.2297→0.1726 | 23.28498→23.30400 |

Kd.10 三次在更接近初始朝向时便出现正合推，支持“微分抑制转动时可能减弱差动，让未对准的船首更早前进”的局部机制。02/03 首次对准时东向位移也更大。

反证同样保留：01 首次越过 −π/2 的 x 几乎相同，01 在 `L+R>0.3` 时 Kd.10 航向已到 -0.282 rad，而 Kd0 为 -0.230 rad，并不对所有标记都更早。实际 u、侧滑、初态和命令相位不同，不能将全部中段增量归因于首个正合推。完整前 20 次非零命令及最近状态在 JSON 内，配对不是控制回调的原子输入。

## CPP 与 Python 的速度生成差异

原 `cpp-baseline` 中的 `src/core/trajectory_planner/src/los_trajectory_planner.cpp`
先以恒定 cruise 积分 x/y（第 130/131 行），再对输出位置间距离累计 `s`，以初始到
末点的欧氏距离 `R` 生成 `v=v0(1-s/R)`（第 143/148/150 行）。它并未以该标注速度
重新积分位置。来源 SHA 保存在 [诊断数据](diagnostic.json)；Python 分支清理后可用
`git show cpp-baseline:src/core/trajectory_planner/src/los_trajectory_planner.cpp`
查看原文，独立 C++ 基线工作区也保留该文件。

当前 [Python LOS](../../../src/core/trajectory_planner/trajectory_planner/los_trajectory_planner.py) 以 `remaining / max(initial_distance,slowdown_distance)` 生成速度，并以该速度积分位置（约第 135–139 行），保留剩余弧长、非负限幅和 3 m 近目标分母修正。

在已经沿直线对准、初始剩余路程 R 大于 slowdown_distance、尚未进入停止圆且忽略离散步长时，Python 的一致模型近似为

\[
\dot s=v_0(1-s/R),\qquad v(t)=v_0e^{-v_0t/R},
\]

而旧 CPP 的恒速位置积分和后标速度给出 `v(t)≈v0(1-v0*t/R)`。对正 t，指数式高于相同 R 的线性式。这是源码支持的数学差异，不是新测得的 CPP 执行结果。

还有独立的时间标签差异：旧 CPP 每 .5 s 输出时，第 i 个输出位置实际积分到了 `(i−1)*.5+.1`，因此名义 3.0 s 行对应约 2.6 s 的恒速位置；3.0 是精确格点，其旧 `lower_bound` 插值问题在该点比值为零，但非格点查询仍存在已记录边界问题。不能只凭同一个配置名字声称两版查询了同一物理时刻。

调度也不同：原 CPP 在 odom 回调中同步规划并更新状态，控制 wall timer 计算缓存值；它没有独立固定 5 Hz 局部规划 timer。Python 使用计划要求的独立 5 Hz 规划进程与 10 Hz 控制，最新状态和参考不同步。本诊断不改变此调度，也不把调度差异等同于速度公式差异。

## 四个真实状态的现有 LOS 执行

从原正式转弯 01 选择沿程约 0/3/6/9 m 的源 odom，用同一首条 25 点路径调用现有 `prune`，再调用现有 Python LOS；状态包括原 x/y/psi/u/v/r/stamp。基于本项目已核查的 map→odom 恒等关系设置 frame，按当前 runtime 的停止圆规则配置 LOS。查询按新规划参考年龄为 0 分别取 2.6/3.0 s，Kd 恢复为 0，仅计算 `2*wrap(theta_ref-psi)` 的未包络和包络后 yaw。

这些是四次冷启动的纯数值规划调用，未进行地图/全艇碰撞校验，未恢复真实 worker 的原子输入与参考年龄；LOS 本身也不预测实际 u/v/r 闭环响应。

| 沿程 / m | 参考速度 2.6→3.0 / m·s⁻¹ | 参考航向 2.6→3.0 / rad | 未包络 yaw 2.6→3.0 |
|---|---|---|---|
| 0 | 0.991095→0.980418 | -0.780065→-0.900065 | -1.560000→-1.800000 |
| 3 | 0.758541→0.725691 | -1.661619→-1.642994 | -0.492978→-0.455728 |
| 6 | 0.661880→0.619317 | -1.590848→-1.581419 | +0.058181→+0.077040 |
| 9 | 0.445068→0.390109 | -1.599864→-1.596072 | -0.153836→-0.146253 |

四点速度分别降低约 1.1%、4.3%、6.4%、12.3%。初始航向在 LOS 0.3 rad/s 饱和区，额外 .4 s 预瞄使误差增加 -0.12 rad、纯 P 航向需求增加 -0.24，方向上支持延长初始转向。所有八次未包络 yaw 均在 ±π 内；这只覆盖本次四输入，不是任意重规划/旧参考年龄的保证。

反证是 3 m 处：3.0 s 查询的参考已进入回摆，负向纠偏需求反而略弱。6 m 时正向回转需求增强，9 m 时负向需求又稍减。增加预瞄并不等于全程以同一方向增加阻尼或更早纠偏。

速度公式的直线近似在 3/6/9 m 状态附近具有解释力，2.6 s 的指数近似分别为 `0.7523/0.6537/0.4361 m/s`，接近实际 LOS 执行的 `0.7585/0.6619/0.4451`；旧 CPP 名义 3 s 的直线线性估算分别为 `0.7148/0.5743/0.1696`。这些 CPP 数字明确是源码公式估算，不能称为 C++ golden 或原始参考遥测。

初始 90° 未对准状态不符合直线假设：Python 2.6 s 实际参考速度约 0.9911，而指数近似只有 0.8072。此时预测艇先向侧方航行，剩余路径没有按对准直线时的速率减少，并可能被速度上限裁剪。不能把指数公式直接套在初段并据此推断实际首段推力。

## 可支持的下一步及限制

现有方法内，Kd 恢复 0、只增加预瞄至 3.0 s，是有具体机制依据的有限候选：初始增大转向需求，中后段降低参考速度；同时回摆相位可能削弱部分纠偏，且不能保证复现旧 CPP 的速度。是否启动由主任务依据固定试验协议决定，本诊断不启动、不选择最好重复、不增加新度量或新控制方法。
