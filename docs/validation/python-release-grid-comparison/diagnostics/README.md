# 直航重复 01：源时间与末端跟踪诊断

**所有数据仅用于解释正式失败，不能替换正式主指标或通过门槛。** 本轮 Python 直航 01 与格内 C++ 直航 01 的正式 RMSE 比例为 1.570461，保持失败。Python 直航 03 只作同版本时序参照，没有拿来替换重复 01。

[straight01.json](straight01.json) 由 [reproduce_straight01.py](reproduce_straight01.py) 从真实 events、summary 和初始 raw map/state 重新计算，保存每个输入的绝对路径与 SHA-256、原始首路径和首轨迹、参数读回、命令时序及分段数值。脚本只依赖 Python 标准库和 NumPy，不导入 ROS 或生产算法，不修改原始文件；不接受覆盖既有输出。

```bash
python3 docs/validation/python-release-grid-comparison/diagnostics/reproduce_straight01.py \
  --results-root /home/usv/usv_migration/results \
  --output /tmp/straight01-diagnostic-NEW.json
```

## 原始几何和启动时序

两版初始地图均为 origin=(-176.5,-210)、resolution=0.5、800×800。Python 与 C++ 状态位置分别为 (23.125764,-10.125775)、(23.125265,-10.125811)，均落在 cell=(399,399)，中心 (23.25,-10.25)，raw cost=0。本例没有 rolling costmap 原点不同导致的世界格中心差异。

首条路径前 24 点完全一致：x=23.25:0.5:34.75，y=-10.25。最后一点为 Python 精确目标 (35.125,-10.125) 与 C++ 格中心 (35.25,-10.25)，总长分别 11.895285 m、12 m。C++ 原路径/轨迹 header 带系统时间，故这里的到达延迟使用实际墙钟接收事件，未把该 header 当仿真时间。

| 首次事件相对 goal 的墙钟延迟 / s | Python 01 | C++ 01 |
|---|---:|---:|
| 有效路径 | 0.231596 | 0.004999 |
| 有效局部轨迹 | 0.234433 | 0.005591 |
| 非零推进器消息 | 2.872433 | 0.008486 |

Python 在有效路径和轨迹已经到达后仍等待非零推力。其源 odom 3.1→3.2 的墙钟接收间隔为 2.787821 s，状态在 goal 后约 0.442 s 已记录 SIMULATION_PAUSED。不能将随后约 2.64 s 等待直接归因于规划工作进程的首次启动。

## 重复采样与同法敏感性分析

harness 每约 0.1 墙钟秒记录一次最新位姿。逐事件把 sample 关联到最近已收到的 odom，所有关联位姿完全相等，0 mismatch。以下“重复”特指同一 odom 源时间戳，而非 sample 自身读取的 /clock 时间。

| 指标 | Python 01 | C++ 01 | Python 03，仅参照 |
|---|---:|---:|---:|
| 正式有效误差样本 | 231 | 245 | 229 |
| 对应独立 odom 源时间戳 | 201 | 228 | 196 |
| 额外重复计入次数 | 30 | 17 | 33 |
| 正式 RMSE / m | 0.0864591 | 0.0550533 | 0.0608279 |
| 每源时间戳一次的诊断 RMSE / m | 0.0644652 | 0.0553653 | 0.0627261 |
| 源时间梯形积分诊断 RMSE / m | 0.0636891 | 0.0564979 | 0.0667118 |

Python 01 源时刻 3.1 被正式计入 24 次，误差约 0.175689 m；C++ 01 的主要重复发生在 11.3，被计入 14 次，误差约 0.043454 m。Python 01 首次非零推力前有 25 个带误差样本，贡献全部平方误差的 44.7%。这说明正式样本权重受到墙钟停顿位置影响；这 25 个样本发生于首路径到达后，不能说成首路径前。

“每源一次”对双方均保留每个真实源时间戳的最后一个已记录 sample。“源时间积分”则使用全部实际 odom，按各自首条有限折线路径计算距离，以相邻源时间间隔梯形积分平方误差，再除以观测源时间跨度。窗口包含 goal 发布时最近的已观测状态，止于采集结束前最后源状态，不向两端外推；Python 01 与 C++ 01 分别覆盖 20.6 s、23.4 s。

两种同法诊断比例为 **1.164360** 和 **1.127282**，仍超过 1.10。正式比例保持 **1.570461**。没有删除启动样本来改变正式判定，也没有将更有利的诊断指标重新命名为验收主指标。

## 按沿航 x 分段的真实运动

使用独立源 odom，区间为 [23,26)、[26,32)、[32,36) m。分段平方误差按源时间积分，相邻区间按线段中点 x 分箱；速度为该区间独立状态中 sqrt(u²+v²) 的算术均值。

| 区段 | Python 时间加权 RMSE / m | C++ 时间加权 RMSE / m | Python 平均速度 / m/s | C++ 平均速度 / m/s |
|---|---:|---:|---:|---:|
| 前段 23–26 | 0.111250 | 0.109974 | 0.645422 | 0.640811 |
| 中段 26–32 | 0.038291 | 0.041934 | 0.630731 | 0.520495 |
| 近终点 32–36 | 0.047590 | 0.012084 | 0.359425 | 0.349416 |

前段相近，中段 Python 的固定路径误差略小且速度更高，近终点误差明显较大。近终点 Python yaw 为 +0.013795～+0.053127 rad，C++ 为 −0.010071～−0.004012 rad；平均 y 分别为 −10.209031 m、−10.239130 m。Python 的运动方向开始接近精确目标 y=-10.125，与 C++ 继续沿 y=-10.25 的事实不同。该现象与末点语义差异相符，但这里没有独立干预实验，不能证明唯一因果来源。

把各区间积分平方误差除以各自全程观测时长后，近终点贡献约占两版总剩余均方误差差值的 79.9%。这是对本次记录的算术分解，包含两版行驶时间和减速过程不同的权重，不是“79.9% 由某个算法缺陷导致”的因果结论，更不改变正式失败。

## 零推力及证据限制

按 20 ms 内接收的 left/right 消息配对，从首次非零到首次观测距离目标不超过 1.5 m：Python 01 为 178 周期、7 次双侧零，主要在启动停顿附近；C++ 01 为 211 周期、0 次双侧零。Python 03 为 202 周期、31 次双侧零，主要伴随中途源时刻 10.9/11.0/11.1 的墙钟停顿。完整零周期和源时间位于 JSON 中。

本例数据证明暂停或时钟更新不及时会影响控制发布和墙钟采样权重，但没有每个控制回调的 dt 或原始 /clock 全流，不能由此逐一判定真实 Gazebo 暂停与短时调度抖动。Python 03 的零周期更多而正式 RMSE 更低，也不支持“01 仅因零推力多而超线”的说法。本诊断没有调整任何控制增益、预瞄、指标或阈值。
