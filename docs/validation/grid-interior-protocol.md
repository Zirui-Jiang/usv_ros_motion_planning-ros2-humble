# 栅格内部起点的追加配对协议

本协议在原矩阵仍执行时固定，追加独立试验；原矩阵及其中未通过的比例保持原记录。
算法、参数、到达容差、几何间隙、10% 比例和性能预算均保持不变。

原起点 `(23,-10)` 位于分辨率 0.5 m 的栅格边界。实测直航第二次的 C++ 首条路径
沿 y=-9.75，而 Python 沿 y=-10.25 并在末端转向另一行。两次首个评价样本的 y
分别为 -9.99971249 与 -10.00027050 m，相差约 0.558 mm，跨越边界后产生了不同
参考线。对应 RMSE 分别为 0.1135226 m 与
0.1426659 m，原 1.10 门槛未通过；这一结果不因本协议而被改写。

追加配置 [scenarios_grid_interior.json](../../scripts/validation/scenarios_grid_interior.json)
将起点、所有目标和受控圆柱一起平移 `(0.125,-0.125)` m，使静止起点位于格内。
各场景相对距离、转弯角度、障碍尺寸与位置关系保持原值。原 world 障碍不平移，
仍执行同样的实际 raw costmap 走廊预检。

| 对象 | 固定值 |
| --- | --- |
| 起点 | `(23.125,-10.125,0)` |
| 直航/圆柱目标 | `(35.125,-10.125)` |
| 转弯目标 | `(23.125,-22.125)` |
| 圆柱中心/半径 | `(29.125,-10.125)` / 1 m |
| C++ 数值版本 | `632734ba31478bdb833e15949287b53ae9334cf3` |
| Python 数值版本 | `4ef01a645ada5fb816c8e1a412fa6cd779723539` |

首先使用同一份配置运行 C++ PID 三场景各三次，再运行 Python PID/LQR 三场景各
三次。每次生成独立 manifest、参数读回、原始事件和前后指纹；实际配置文件 SHA256
保存在运行记录中。C++ LQR 的无效闭环另行诊断，不以未运行的结果作性能比较。

比较报告分别处理原协议和追加协议，不跨协议按相同名称/序号匹配，不选择某次较优
结果替代其他重复，不修改原始 JSON。追加协议的结果只能表述为对应坐标与环境下
的验证；原场景揭示的栅格边界敏感性仍作为限制和回归证据保存。
