# Python 迁移差异与正确性边界

本文记录源码级迁移范围、保留行为、缺陷修复和对照原则。它不报告构建或闭环试验通过情况；动态结果见 [迁移状态](python-migration-status.md)，操作方法见 [使用指南](python-navigation-guide.md)。

## 1. 对照版本与范围

原始 C++ 基线为 `cpp-baseline` 标签，Python 开发分支为 `refactor/python-navigation`。比较时必须记录实际提交，不用分支名称代替固定版本。

| 部分 | 原实现 | Python 版本处理 |
| --- | --- | --- |
| 全局搜索 | 一套八邻域 A* 类，通过标志选择 A* / Dijkstra / GBFS | 保留三种模式和欧氏步长代价；增加输入校验和计算预算 |
| 路径处理主链 | 距离最近航点裁剪；可选等弧长重采样 | 保留主链，并对候选结果碰撞复核 |
| `path_processor` 工具库 | RDP、Savitzky–Golay 已存在实现 | 提供纯 Python 函数和类；未自动启用 |
| 轨迹生成 | LOS 航向引导与运动学前向预测 | 迁移 LOS，修复边界、时间、速度和终点语义 |
| 控制 | Otter 速度/航向 PID，六状态离散 LQR | 保留模型及分配语义，校验有符号体轴速度，明确求解失败 |
| LiDAR 建图 | 按束更新的整数占据证据图及 ROS 接口 | 迁移内核和 ROS 节点，增加准确 TF、扫描去重、队列与时钟管理 |
| ROS 调度 | C++ simulation 将基础设施与算法结合 | Python 适配器与独立规划进程，C++ 保留定位和 Nav2 costmap 支撑 |
| 仿真及界面 | Gazebo/波浪/水动力/推进器/URDF/RViz | 复用原实现及资源，未作语言重写 |

配置目录仍有 hybrid_astar、visibility、quartree、DWA、MPC、ORCA、APF 等模板，不能据其文件名认定当前工厂已经实现或启用这些算法。当前可选全局算法为 A*、Dijkstra、GBFS，轨迹为 LOS，控制为 PID、LQR。

LiDAR 建图使用已有姿态和 TF，不做扫描匹配或位姿估计，不能称为 SLAM。AIS/导航雷达融合、航迹关联、CPA/TCPA、COLREGs 规则决策均不是此次迁移新增的已实现功能。

## 2. 保留目录与非活跃依赖

已迁移的六个原包在原目录添加同名 Python 导入包，通过 `ament_python` 安装；`sim_env` 保留混合构建。原 C++ 源码和部分 CMake 描述仍在仓库中供核对，当前 Python 包的 `package.xml` 决定实际构建类型。

`common/src/geometry/curve` 下的 Dubins、Reeds–Shepp、Bezier、B 样条、三次样条、五次多项式等，在原 common CMake 中被编译，但当前 `src` 导航调用链未发现 common 外使用这些曲线的调用。它们没有被列为首版 Python 必须实现的依赖，也没有因源文件保留而成为可导入的 Python 算法。后续启用时需要单独实现、测试和评估运动学适用性。

原 `src/plugins/gazebo_plugins`、`src/plugins/rviz_plugins/goal_set_plugin`、`dynamic_xml_config`、`dynamic_rviz_config` 等插件与配置工具继续保留。保留工具不意味着其所有配置字段都被新的 `main.launch.py` 消费。

## 3. 算法与数据语义差异

### 网格搜索、裁剪与重采样

- A*、Dijkstra 的边代价保持单位网格步长：水平/垂直为 1，对角为 `sqrt(2)`，未新增按 costmap 数值连续加权的代价项。
- 障碍阈值保持 `254 * obstacle_factor`；Nav2 值 255 为未知，纯算法接口默认按障碍处理。当前 ROS 导航配置未开放全部纯内核选项，不能把内核的任意构造参数直接放入项目 YAML。
- 原代码允许从膨胀代价较高的当前格向较低代价格探索。新接口明确拒绝阻塞起终点，因此原本依赖“从阻塞起点向外逃逸”的行为不再被接受。这属于端点契约改变，应在差异用例中单独记录。
- 原 A* 仅验证线性索引范围，跨行的邻居可能仍具有合法索引；新实现先独立检查 x/y 边界。
- 对角移动默认保留原允许切角的设置，纯内核支持禁用；路径安全检查仍是栅格分段采样，不等同于完整船体扫掠碰撞证明。
- 搜索堆使用确定性平局规则；多条等代价路径不保证逐点与 C++ 相同。比较可达性、端点、代价和碰撞属性，不把单一平局路径当作唯一真值。
- 裁剪仍选择离船最近的航点，等距离时选择最后一个；不是沿路径投影的进度估计，也不能单独解决回环路径的错误分支匹配。
- 等弧长重采样保持首尾姿态，单位为米；重复点和非正采样间距显式处理。候选连线可能跨越原折点，新版本碰撞检查失败时退回原有效网格路径。

### RDP 与 Savitzky–Golay 的实际调用状态

原 `path_processor` CMake 将 RDP 和 SG 编入库，但原 `PathPlannerCore::makePlan()` 主链只看到 `resample()` 调用，没有创建 RDP/SG 处理器；对当前 `src` 的调用检索也未发现该库外的 RDP/SG 使用。因此，“默认一直启用路径平滑”不是该仓库的真实行为。

Python 版本同样只在主链使用配置控制的重采样。RDP/SG 作为可直接调用的工具导出，默认未进入 `sim_env.runtime`。使用者若主动接入，需要自行验证修改后路径的碰撞、曲率和动力学约束。

| 工具 | 保留内容 | 修复或明确化 |
| --- | --- | --- |
| RDP | 点到有限线段距离判据；阈值 `delta/epsilon`；指定最大间距时的插值及最短航向插值 | 空/短路径安全处理；迭代栈代替递归；默认 `max_interval=None` 表示不插值，拒绝旧默认 0 导致的除零 |
| SG | 默认七点二阶核 `[-2,3,6,7,6,3,-2]/21`，位置平滑 | 少于窗口长度时保留输入，固定首尾姿态，使用端点 padding，内部航向根据平滑结果计算 |

SG 在足够长路径的内部点保留默认核结果；边界与航向是明确修复区，不要求与旧边界输出完全相同。处理器中的 `set_obstacles()` 仅保留障碍数据副本，RDP/SG 不消费该数据，不应把它理解为障碍约束平滑器。

### LOS、轨迹与控制

LOS 保留航段方向、横向偏差与前视距离构成的视线引导，以及限幅 yaw rate 的前向预测。新版本使轨迹时间戳对应真实积分时刻，位置预测和速度剖面使用一致速度，按剩余路线长度得到非负减速参考。

轨迹时间为相对 `stamp` 的秒，航向插值采用最短角差。控制器按当前状态时间与轨迹时间的年龄选择参考，使用明确的全局目标判断完成，而不是局部预测窗口末点。

导航调度把网格中心末点替换为请求的精确目标，并将 LOS 停止容差限制为不大于当前控制器完成容差。预览到预测到达后的零速点时，只要实际船还没到达目标且轨迹存在有效接近速度，控制器继续使用接近速度；不能因此取消远离终点的中途停车指令。

PID 保留原差动推力分配的归一化标定，未额外除一次 `max_force`。LQR 保留原六状态线性化与前向 Euler 离散结构，通过线性求解替代显式矩阵求逆；未收敛或超时返回零命令及失败状态，不使用未完成的增益。PID 增益热更新保留历史状态，任务重置才清积分。

`nav_msgs/Odometry.twist` 约定是 `child_frame_id` 船体坐标速度。fake localization 负责将 Gazebo 世界速度转换一次；控制器保留 u/v 符号，避免再旋转一次或对有符号状态取绝对值。

### LiDAR 累积图与导航 costmap

mapping 保留整数证据更新：经过格减 25、命中格加 55，并限制到 0..100；未知格初始值为 -1，所以第一次命中为 54。这不是经过概率标定的 log-odds，也不是标准概率占据更新公式。

新实现按扫描自身时间戳和 frame 查询 TF，同帧扫描最多积分一次；有限队列和墙钟超时控制等待，地图定时发布不重复积分扫描。NaN、负无穷、负距离和低于最小量程的束跳过；无回波/超量程束只清除有效射线范围，不在远端伪造障碍。二维裁剪修复跨行写入和地图边缘假命中，时钟回跳清 TF、扫描记录及地图证据。

`/otter/map` 是 mapping 的 `OccupancyGrid`；`/otter/costmap_raw` 是独立 Nav2 obstacle/inflation 层的原始代价图。当前 static layer 未启用，不能把两条图链路描述为已经融合。

## 4. 已落实的缺陷修复与验收方式

以下“修复”指源码行为及对应回归目标；完整部署与闭环结果仍需查看状态文档。

| 问题 | 新行为 | 应覆盖的回归 |
| --- | --- | --- |
| A* 邻居线性索引跨行 | 先检查二维坐标再读图 | 行边缘伪相邻、不连通、边角、非零地图原点 |
| 阻塞/越界端点未明确定义 | 阻塞返回 `NO_PATH`，越界/非有限输入返回 `INVALID_INPUT` | 阻塞起点、阻塞终点、未知区域、地图边界 |
| 搜索可能长时间占据调度线程 | 独立规划进程，搜索时间及展开数限额 | 超时、展开数耗尽、重复请求替换 |
| 重采样间距非正或折点切障碍 | 校验间距，复核候选路径并可回退 | 0/负间距、重复点、大间距绕障路径 |
| RDP 默认间距除零、空路径越界 | 显式默认语义和输入检查 | 空/单点、重复端点、0 间距 |
| SG 短路径清空、末点漂移 | 保留短路径和端点姿态 | 1..6 点、边界、默认内部卷积核 |
| LOS 空路径提前访问、远航点航向误差未赋值 | 输入先验证，完整航段分支 | 空路径、单航点、远距离下一航点 |
| LOS 积分时刻与输出时刻不符 | 每个输出时间点对应实际积分状态 | 非 0.1 s 整数倍、输出间隔小于内步长 |
| 直线距离归一化造成负速 | 使用路线剩余长度与非负速度范围 | 绕行、长折线、接近终点、重复点 |
| 按预测窗口末点或网格中心提前完成 | 精确目标、协调容差、实际状态完成判据 | 目标靠近格边、局部窗口短于全程、PID/LQR近终点 |
| 预览到预测到达后的零速参考而停在容差之外 | 到达前保持已有接近速度，真实到达后停艇 | 静止起步且目标较近、晚收到的短终点轨迹 |
| 体轴速度被重复变换或丢失符号 | 定位转换一次，控制消费有符号 u/v/r | 非零 yaw、负横向速度、LQR状态误差 |
| LQR 未收敛仍可能使用结果 | 迭代数及求解时间限额，失败返回零推力 | 病态参数、迭代上限、超时 |
| 建图重复积分与无效射线 | 扫描按时间去重、准确 TF、无效束过滤 | 重复/过时扫描、TF晚到、扫描掉线、边界射线 |
| 参数前缀、拼写与障碍阈值层级不一致 | 显式兼容、冲突拒绝、启动日志输出最终值 | 原 YAML、旧别名、冲突值、未知键 |
| raw costmap 时间戳字段选错 | 使用 `header.stamp`，不依赖未填的 metadata 时间 | 有新 header、metadata.update_time=0 的真实发布格式 |
| 新地图下继续控制旧轨迹 | 收图时和接收规划结果时用最新地图复核 | 轨迹中新障碍、旧图工作结果延后返回 |
| 取消/目标替换后接受旧结果 | 任务版本检查与参考清理 | 规划尚未完成时取消或替换目标 |
| 状态/地图/参考失效后继续推进 | 每个控制周期检查新鲜度，持续零命令 | odom/map断流、参考过期、帧不匹配 |
| 暂停与时钟回跳处理不完整 | steady timer发零推力；回跳清任务、输入、TF和建图历史 | 暂停、恢复、时间回退并重新发目标 |
| 工作进程提交异常逃逸 | 提交和取结果均捕获异常，转规划错误和零推力 | 提交失败、损坏进程池、异常规划结果 |

Nav2 Humble 的 `prepareCostmap()` 设置 `header.stamp`，而 `metadata.update_time` 只在其 GetCostmap 服务响应路径中赋值。此前若按后者判断话题数据新鲜度，会把持续发布的图视为时间 0，进而一直等待地图。该修复依据实际发布源码，而非依赖测试发布者替它填字段。[Nav2 Humble publisher](https://raw.githubusercontent.com/ros-navigation/navigation2/humble/nav2_costmap_2d/src/costmap_2d_publisher.cpp)

## 5. Python/C++ 如何比较

将对照分为保留行为和明确修复行为，并记录每例属于哪一类。

| 对照对象 | 判等或验收原则 |
| --- | --- |
| 栅格转换和地图元数据 | 相同原点/分辨率/尺寸下坐标转换一致，整数栅格索引精确比较 |
| A* / Dijkstra | 可达性、端点、路径代价在预先规定的浮点容差内一致；等代价不同路径允许存在 |
| GBFS | 比较模式、可行性、路径长度和搜索量，不要求最短路保证 |
| 裁剪/重采样 | 检查保留航点、端点姿态、采样位置、航向环绕误差与碰撞属性 |
| RDP / SG | 保留算法的内部结果对照；空输入、边界、终点等修复区使用新契约 |
| LOS/轨迹 | 时间严格有序、位置时间一致、速度非负、航向/角速度合法、终点语义正确 |
| PID / LQR | 固定状态、模型、参考和初始历史，比较中间误差、分配/模型矩阵及最终命令；保留符号和单位 |
| 建图 | 固定按时间排序的扫描与TF，保留按束更新顺序；正常束可逐格比较，重复/无效束按修复后预期验收 |
| 调度与闭环 | 比较目标到达、碰撞/间隙、横向误差、推力有界、取消/断流响应、耗时分位数 |

不要求 Python 复现 C++ 的未定义值、越界访问、负速度、重复积分或参数静默失效。数值容差和闭环阈值应在运行前固定，不能看完结果后为迁就某个实现改阈值。

当前碰撞检查沿路径段按不大于半格距离采样；它不覆盖船体完整扫掠体，也不是连续空间无碰撞证明。验收脚本中针对受控圆柱的 footprint 几何间隙是另一层独立度量，不能用普通点路径通过代替该指标。

`navigation.planning_timeout` 限制搜索，不是包含序列化、LOS、碰撞复核、ROS 队列和控制器的全链路硬期限。规划 worker 最多一个执行项、一个最新待处理项；正在执行的工作不能保证被 `Future.cancel()` 立即中止，旧任务依靠版本号拒绝结果。退出时等待 worker 收尾也不构成强制进程终止策略。

## 6. 原标签与基线启动修复分别记录

为便于对照，独立 C++ 基线工作区使用 `baseline-validation` 分支，当前位于 `/home/usv/usv_migration/baseline`。其允许的最小修复范围为：

1. 补齐 `libsim_env` 的安装，覆盖普通安装时共享库遗漏的问题。
2. 在原 launch 基础增加 `baseline_validation.launch.py`，提供 GUI/headless/RViz 和 `controller_name` 选择，将选择传给原来已经支持 PID/LQR 的工厂参数。

这些属于安装、启动和参数注入修复，不是 Python 算法改进，也不应改写 C++ 数值算法。报告应同时记录原 tag 提交、validation 补丁提交、补丁文件范围、实际入口和参数快照；不能只写“cpp-baseline”而隐藏启动补丁。基线 launch 参数名存在并不说明已选中 LQR，验收工具还需要查询节点中的实际控制器名称。

完整对照入口和输出语义见 [ROS/Gazebo 验收说明](../scripts/validation/README.md)。C++ 没有的服务或失效保护应记录为 `unsupported`，依赖不足或场景不满足条件应记录为 `blocked`；脚本 `--dry-run` 标记的是未运行计划。上述状态均不等于已通过闭环验收。
